# DR-0092: テストを英語側のみに置き `.ja/` から外す

## Context and Problem Statement

`.ja/` 配下に 35 本のテストが英語側と対で存在し、両者の差はコメントの言語とパス解決だけである。DR-0073 が定めるとおり `.ja/` は正であって実行物ではなく、workflow の discovery も `workflows/` を flat に読むだけなので `.ja/workflows/` は走らない。走らないコードに対する振る舞いテストが、保守対象として二重に積まれている。

## Decision Drivers

- `.ja/` 側のコードは本番で実行されない (DR-0073「英語側は実行物であって正ではない」)
- 同じロジックを 2 回走らせても、片方が落ちるときもう片方も落ちる
- ミラーのずれは、両側が互いに整合したまま古びる形で起きる。振る舞いの二重実行では検出できない
- テストを 1 本足すたび 2 ファイルの保守が発生し、パス解決の差分でミラー時の事故が起きる

## Considered Options

- Option A: テストは英語側のみに置き、`.ja/` からは外す
- Option B: 現状維持。両側に同じテストを置く
- Option C: `.ja/` 側は振る舞いテストをやめ、両側の構造一致だけを見る比較テストに置き換える

## Decision Outcome

Option A を採用する。`.ja/` 側のテストが唯一持ちうる価値はミラーのずれの検出だが、それを果たせないため。英語側だけ修正して `.ja/` を放置した場合、`.ja/` のコードとテストは互いに整合したまま古びるので両方 green になる。検出できるのは「テストだけ反映してコードを反映し損ねた」順序のときに限られ、規約が求める同一コミットでの反映を守る限り発生しない。

Option C は将来の選択肢として残す。構造比較はずれを実際に捕まえるが、比較の粒度 (関数名の集合か、AST か、行数か) を決める設計が要り、ずれが実害として現れてから決めたほうが精度が出る。

### Consequences

- Good, because テストの追加と改修が 1 ファイルで完結し、パス解決の差分に起因するミラー事故が消える
- Good, because 実行されないコードへの検証がなくなり、テストの実行時間と読む量が半分になる
- Bad, because `.ja/` 側のコードは自動検証を持たなくなる。散文としての正しさは人間のレビューに残る
- Bad, because ミラーのずれは引き続き未検出のまま。この DR はその状況を悪化させないが、改善もしない

### Confirmation

`git ls-files '.ja/**/*.test.js'` が 0 件を返すこと。`rules/conventions/MIRROR.md` § 反映の形にテストの扱いが明記されていること。

## Pros and Cons of the Options

### Option B: 現状維持

両側に同じテストを置き続ける。

- Good, because 規約の変更が要らず、既存の 23 ディレクトリに手を入れずに済む
- Bad, because ミラーのずれを捕まえられないまま、保守だけが 2 倍かかる
- Bad, because テストを足すたびパス解決を書き換えるミラー作業が発生し、そこ自体が事故の発生源になる

### Option C: 構造比較テストへの置き換え

`.ja/` 側の振る舞いテストをやめ、両側のコード構造が一致することだけを検査する。

- Good, because ミラーのずれを実際に検出できる。Option A が残す穴を塞ぐ
- Bad, because 比較の粒度を決める設計が要る。散文は翻訳され、コード構造は同一という規約をどう機械で表すかが自明でない
- Bad, because ずれの実例がまだ無く、何を検出したいのかが仮説の域を出ない

## More Information

### Before / After comparison

| 項目                  | Before                      | After               |
| --------------------- | --------------------------- | ------------------- |
| テストファイル数      | 英語側 35 + `.ja/` 側 35    | 英語側 35           |
| テスト追加時の作業    | 2 ファイル + パス解決の書換 | 1 ファイル          |
| `.ja/` 側コードの検証 | 振る舞いテスト              | 人間のレビュー      |
| ミラーのずれの検出    | できない                    | できない (変化なし) |

### Transition Plan

1. `.ja/` 配下の `**/*.test.js` と、テスト専用のヘルパー (`_git-fixture.js` 等) を削除する
2. `rules/conventions/MIRROR.md` § 反映の形に、テストは英語側のみに置く旨と理由を追記する
3. 英語側のテストが全て green であることを確認する

### Reassessment Triggers

- ミラーのずれが実害として現れる。英語側だけ直して `.ja/` が古びた状態が、後続の作業で誤読を生んだとき
- `.ja/` 側のコードが実行される経路ができたとき。workflow の discovery が `.ja/` を走査するようになる、`.ja/` 側の script を直接叩く運用が始まる、など
