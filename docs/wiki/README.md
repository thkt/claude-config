# docs/wiki

実装者が「今このプロジェクトではどうやるか」を引く場所。繰り返し現れる定型手順と規約、再発する指摘を過去の PR / issue から蒸留して置く。issue の Plan やレビューで毎回同じ説明を書く代わりに、ここ 1 箇所を参照する。

## ページの種類

1 共通項 1 ページで、節は 内容 → 定型手順 → 参照コード → 由来 → 根拠 の順。根拠が 1 件だけの共通項は `_candidates.md` に置かれ、2 件目が現れたらページへ昇格する。初出でも根拠が 2 件揃っていれば直接ページになる。1 回の run が動かすページ数には上限があり、昇格できるのに溢れた分は `_candidates.md` の昇格待ちへ回って次の run で先に処理される。

`kind: structure` を持つページは共通項ではなく、1 つの glob 契約グループの構造を書く。グループとは、同じ境界と契約を共有するファイルの集まりで、`globs` が表す単位そのもの。`workflow-structure.md` が `**/workflows/**/*.js` の 7 ファイルを 1 枚に収めるのはそのため。節は 内容 → 境界 → 契約 → 要求 → 参照コード → 由来 で、定型手順 と 根拠 は持たない。根拠 2 件の閾値もページ数の上限も掛からない。共通項ページと同じ glob を持ってよいが、共通項ページが述べた内容は書かずページ名で参照する。

## 由来

由来はこのページの内容を決めた記録への参照で、その記録が置き換わったらページの書き換えが必要になる密接なものだけ張られる。判定は反実仮想テスト「その記録が置き換わったらこのページは書き換えが必要になるか」で、Yes のときだけ張る。

節を持つ条件は種類で違う。共通項ページは密接な記録が無ければ節ごと持たない。構造ページは見出しを必ず持ち、条件を満たす記録が無いときは中身が空になる。6 節の並びを `skills/scribe/tests/skill_contract_test.py` が完全一致で固定しているため。

由来が指す記録が置き換わったときは、その変更単位でページを書き換える。リンクの張り替えだけでは足りず、本文の記述が今も成り立つかを見る。リンク側は `skill_contract_test.py` が検査する。

## 育て方

`/scribe` が、closed になった PR / issue から自動で抽出する。初回は全履歴を読んで基礎化し、以降は前回の scribe PR マージ以降に closed になった分から増分更新する。追加 / 修正は PR で提案されるので、レビューしてマージする。マージが承認になる。手動追記も可。
