# hook の失敗は「何も起きない」形で現れる

## 内容

hook が落ちても Claude Code はエラーを出さない。促しが出ない、記録が残らない、という「何も起きない」状態になるだけで、実装が動いていないことと区別が付かない。動いたことを外から確かめる手段を先に用意する。

## 定型手順

1. hook 本体へ標準入力から payload を渡し、単体で期待どおり動くことを確かめる
2. 配線後に契機の操作を打ち、届くはずの出力が届くか見る
3. 届かないときは hook の先頭でログを書き、呼ばれているかを切り分ける
4. 呼ばれていれば判定の各ゲートに、呼ばれていなければ実行権限と PATH を疑う

## 参照コード

- `hooks/_lib/scribe_trigger.py` の `DEFAULT_GH`（PATH が切り詰められるので絶対パスで引く）
- `hooks/lifecycle/recall_index.py` の `DEFAULT_RECALL`（同じ形の先例）

## 根拠

- #519 実行ビットが無く hook が起動しなかった。エラーは出ず促しが出ないだけだった
- #522 PATH が切り詰められ bare な `gh` が FileNotFoundError で落ちた。例外は表に出ない
- #523 `cd ~/.claude` の `~` が展開されず、存在しないディレクトリを判定していた
