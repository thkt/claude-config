# 規約の追加は実測を先に置く

## 内容

散文規約や記法規則を足すとき、既存の検査が何を見ているかと、規則が名指す主体が実際にその操作をしているかを先に測る。推測のまま書くと、規則は書かれるが誰も検査せず、主体の名前が実物と違ったまま残る。測り方は、陽性コントロールを通して検査が生きていることを確かめ、そのうえで対象を通す。

## 定型手順

1. 規則を足す前に、その観点を見る既存の検査 (linter、hook、CI) の設定を読む
2. 陽性コントロールを通し、検査が読み込まれていることを確かめる
3. 規則の対象を通し、無指摘なら「配線されていない」と記録する。指摘が出るなら規則は不要
4. 規則が主体を名指すなら、その主体が実際に操作しているかを実測で確かめる
5. 実測できなかった箇所は inferred と明記し、実機検証で棄却されうる前提として残す

## 根拠

- #369 PROSE.md の語彙規則を見る検査がどこにも配線されていないことを実測した。textlint に対象文を通して exit 0 の無指摘を確認し、陽性コントロール 3 件が検出されることで設定の読み込み自体は生きていると切り分けた
- #363 harness の現状を Node v26.7.0 で実測してから契約を直した。`console` は ambient な vm の値が見えているだけで本番の挙動とは違う、という区別が実測で出た
- #264 `.ja` のスラッシュ前後を詰める主体を実測で特定した。元の記述と build の記述はどちらも formatter としていたが、formatter バイナリの実体は oxfmt 呼び出しと EOF 改行だけで、詰めているのは textlint hook だった
- #384 `.ja` の点検で、推測を実測へ置き換えた 3 箇所を Review focus に挙げ、そこだけは根拠を確かめるよう求めた
