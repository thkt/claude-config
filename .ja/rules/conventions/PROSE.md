# Prose

ソフトウェア開発の文章を、読み手が基準を再構成できる語と、役割を予測できる文で書く。対象はテスト記述、Issue/PR 本文、コミットメッセージ、plan、コードコメント、技術ドキュメント。確定前に成果物を一度読み返し、読み手が基準を再構成できない語があれば、以下の表への掲載を問わず具体化する。

## 具体的に定義する

右列は例示であり、これらに限らない。次節の表も同じ。同じ問題を起こす語は、同じ行のあるべき形に書き換える。

| あるべき形                               | 書き換える語句                                                     |
| ---------------------------------------- | ------------------------------------------------------------------ |
| 条件と期待結果を書く                     | 正しく / 正常 / 異常 / correct / normal / abnormal                 |
| デフォルト値か前提条件を書く             | 通常 / 一般的 / 標準的 / usual / ordinary / standard / general     |
| 具体的な値か振る舞いを書く               | 期待値 / 意図どおり / 仕様どおり / as intended / as specified      |
| 変換、検証、永続化など実際の操作名を書く | 処理する / 処理 / process                                          |
| ユーザー名、注文一覧など中身を書く       | データ / 情報 / data / information                                 |
| 確認した条件を列挙する                   | 問題なく / without issues                                          |
| 具体的な操作と判断基準を書く             | 適切に / きちんと / appropriately / properly                       |
| 具体的な性質か操作を書く                 | 堅牢 / 活用する / 掘り下げる / robust / leverage / delve           |
| 実処理と結果を表す動詞を使う             | 効く / 重ねる / 支える などの抽象動詞                              |
| 助詞と動詞を補った句にする               | 変更影響 / 文脈保持 などの圧縮名詞。定着した専門用語は書き換えない |
| 句をやめて指す内容を直接書く             | 他言語の慣用句の直訳。定着した句は書き換えない                     |

## 状態比較の基準

| あるべき形                     | 書き換える語句                            |
| ------------------------------ | ----------------------------------------- |
| 具体的な数値か閾値を書く       | 大量 / 少量 / large amount / small amount |
| 具体的なサイズか比較対象を書く | 大きい / 小さい / large / small           |
| 範囲とソートキーを書く         | 最新 / 最古 / latest / oldest             |
| 計測値と閾値を書く             | 速い / 遅い / fast / slow                 |

## スコープを明示する

モデルは、ある項目への指示を別の項目へ一般化せず、明示されていないスコープも推論しない。そのため、ルール/Spec/プロンプトを書くときは、意図したスコープを文に書く。

| 意図       | 書き方                               |
| ---------- | ------------------------------------ |
| 例示リスト | A / B / C など (これらに限らない)    |
| 網羅リスト | A / B / C に限る                     |
| 広く適用   | 最初のセクションだけでなく全体が対象 |

## 一文と一段落の上限

文が長いほど、読者が理解する割合は下がる。一文は 60 字を上限とし、超えたら主語と述語の組で分ける。一段落は 300 字を上限とし、超えたら段落を割るか、表かリストに変える。

## 中心を明示する

読み手が本文から要点を取り出す作業を、書き手が先に済ませる。中心の主張を決まった位置に置き、周辺の情報と競合させない。読み手が前の内容を覚えていなくても読み進められる形にする。

| ルール             | 指示                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------- |
| 中心を冒頭に置く   | 各セクションの冒頭 1 文に、そのセクションで最も重要な主張を置く。要点を読み手に抽出させない |
| 強調は中心だけ     | 強調するのは中心の主張に限る。複数箇所を強調すると、どれが中心か読み取れなくなる            |
| 前方参照を書かない | 「後述の通り」「詳しくは下で」は書かない。その場に書くか、リンクへ逃がす                    |
| 条件と結論を分ける | 1 文に条件と結論を同時に入れない。結論を先に書き、条件は次の文に置く                        |
| 節を入れ子にしない | 入れ子の節と二重否定を書かない。肯定形の短文に割る                                          |
| 呼び名を増やさない | 同じ対象に複数の呼び名を与えない。指示語で受けるか、同じ語を繰り返す                        |
| 手順は 1 行 1 動作 | 手順は 1 ステップ 1 文にし、各行を動詞で始める                                              |
| 表へ戻らせない     | 表の行を読むために本文へ戻る必要がある書き方をしない                                        |

## 予測可能な散文

読者が前の文から次の文の役割を予測できる形で書く。文と文の関係を読者の推測に委ねず、文頭と文末で示す。

| ルール             | 指示                                                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 接続詞で予告       | 対比、逆接、因果、具体例へ移る文は、文頭の接続詞 (一方で、そのため、たとえば など) で役割を予告する                                         |
| 否定は前提の後     | 伝えたい内容を直接書く。否定を使うなら、読者が X と考える理由を先に書く                                                                     |
| 疑問を回収         | 問題を書いたら原因か対処を、操作を書いたら結果を次の文で受けてから、別の話へ移る                                                            |
| 指示語で接続       | 指すものが直前で一意なら「その」で前文を受け、同じ話の継続を示す。候補が複数なら名詞を書き直す                                              |
| 主語を保つ         | 誰の判断か、何の動作かが変わる文には主語を置く                                                                                              |
| 動作で書く         | プログラム、ファイル、テストは実際の動作を述語にする。formatter が嫌がる でなく formatter が行を複製する                                    |
| 状態は実条件で書く | 生きている / 死んでいる / 生存 は実際の条件に置き換える。hook が死んでいる でなく hook が発火しない。デッドコードのような定着した用語は除く |
| 温度感の転換       | 問題は負担が分かる文末 (できない、必要がある)、改善後は負担減が分かる文末 (できるようになる) で書き分ける                                   |
| 内容から書き始める | 伝えたい内容から直接書き始める。「本質は〜」「鍵は〜だけ」型の演出は置かない                                                                |

## 既知の形に合わせる

読者は本文を読む前に見た目から難しさを判断し、読みにくさの出所を区別しない。そのため見慣れない形で書くと、内容そのものが難しいと受け取られる。読者に判断も行動も求めない文書は以下の判定の対象外。OUTCOME、リファレンス表、用語集などが当たる (これらに限らない)。

| ルール             | 指示                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------ |
| 形の出所を選ぶ     | テンプレート > 外部の定型 > 認知の順序 の順に取る。兄弟文書は出所にしない                  |
| 兄弟を判定する     | 兄弟の節が「気づく → 理解する → 判断する → 行動する → 確認する」に対応しないなら真似しない |
| 借りるのは形だけ   | 借りるのは節の並びと節名まで。文と語や、他節に反する箇所は真似しない                       |
| 逸脱は理由とセット | 既存の形から外れるときは、その理由を文書内に書く。書けないなら形を戻す                     |

## 文書更新文を削る

文が更新するのは「状況」か「文書」かで判定する。状況は対象の事実、判断、確度を指し、文書はその文書自身の見え方や進行を指す。文書だけを更新する文は削る。AI 生成の本文に混入しやすい典型は以下の 4 型 (これらに限らない)。

| 型             | 説明                                       |
| -------------- | ------------------------------------------ |
| 進行実況       | これから書く内容や手順をその場で宣言する文 |
| 性格づけ宣言   | 文書自身の範囲や性格を宣言する文           |
| 態度のない弁明 | 退ける誤読を特定しないまま補足する文       |
| 改稿の告知     | 以前の記述や覆った前提を述べる文           |

## 重複文を削る

隣接するコード・表・見出しから読み取れる文は削る。条件、例外、失敗時の挙動は重複ではないので、短くするために落とさない。

| 型                 | 説明                                                             |
| ------------------ | ---------------------------------------------------------------- |
| コード紹介         | 直下のコードが示すことを散文で言い換える文                       |
| 帰結の説明         | 指示や分岐がもたらす結果を述べる文。指示だけを残す               |
| 実測エクスキューズ | 数値の由来や計測値を書き残す文。鮮度が落ちるだけで行動を変えない |

## 文書の長さを内容に合わせる

前 2 節が文を単位に削るのに対し、この節はセクションを単位に判定する。実質を覆う長さを取り、かさを増やす節は置かない。かさ増しの典型は以下の 3 型 (これらに限らない)。

| 型               | 説明                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 埋め草セクション | 他節の再掲か一般論だけで構成され、削っても文書の主張が変わらない |
| 重複する要約     | 本文で既に述べた内容を末尾でまとめ直す                           |
| 定型の枠         | テンプレートを埋めるために置き、この文書固有の内容が入っていない |
