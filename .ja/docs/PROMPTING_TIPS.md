# Prompting Tips

Claude Code のための効果的なプロンプティングテクニック。

## やり直し・改善

| プロンプト                                                             | 効果                         | タイミング     |
| ---------------------------------------------------------------------- | ---------------------------- | -------------- |
| 「今わかっていることを踏まえて、これを破棄しエレガントな解で実装して」 | 蓄積された文脈でより良い実装 | 平凡な実装の後 |

## レビュー・検証

| プロンプト                                                                 | 効果                                  | タイミング |
| -------------------------------------------------------------------------- | ------------------------------------- | ---------- |
| 「この変更を厳しくレビューしてくれ。テストに合格するまで PR は作らないで」 | Claude を厳格なレビュアーに切り替える | PR 作成前  |

## コンテキスト・計算

| 戦略                                     | タイミング・理由                                             |
| ---------------------------------------- | ------------------------------------------------------------ |
| プロジェクトあたり MCP ツール ≤10        | 各ツール定義がコンテキストを占める                           |
| 必要なプラグインのみ有効化               | それぞれがトークンオーバーヘッドを増やす                     |
| 要求に「サブエージェントを使って」を追記 | 大きなタスクを並列化し、探索の文脈を主セッションから隔離する |

## デバッグ

| プロンプト                         | 効果                     | タイミング |
| ---------------------------------- | ------------------------ | ---------- |
| 「失敗している CI テストを直して」 | 細かく管理せずに走らせる | CI 失敗時  |

## ワークフロー

| テクニック                                       | 効果                       |
| ------------------------------------------------ | -------------------------- |
| `/think` → 別の Claude セッションでレビュー      | 計画品質の向上             |
| 何かおかしいと思った瞬間に `/think` に切り替える | 悪い経路で時間を浪費しない |
