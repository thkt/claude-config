# id の採番

unit と受け入れテストの id を振る。形は `U-001` と `T-001` の連番で、T-NNN は plan 全体で一意にする。

重複した id は build の Load が id クロスチェックで止める。対象 repo の規約と合わない番号は、実装時の改番へ頼ることになる。

| 対象 repo | 振り方                                                                             |
| --------- | ------------------------------------------------------------------------------------ |
| 接頭辞つきの id を使う | `T-SK077` のようにその規約へ合わせる。番号は同じ接頭辞の repo 全体での最大値の次から |
| 接頭辞なし | plan 全体の一意性は同じファイル内までは届かない。テストを書き込むファイルで既に使われている番号を避ける |
