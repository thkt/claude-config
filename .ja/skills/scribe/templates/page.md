# wiki ページテンプレート

/scribe が Phase 6 でページを作成/昇格するとき、この骨格で書く。1 共通項 1 ページで、ファイル名は kebab-case の `<共通項名>.md`。`<...>` は生成時に置き換える。

## Template

各ページは frontmatter の `globs` と `scenes` から始め、内容 → 定型手順 → 参照コード → 由来 → 根拠の順で構成する。`globs` はこの決まりごとが効く実装ファイルのパターンで、ファイルを触る時点で届かない運用規約は空配列にする。空配列であること自体が「実装時には届かない」という情報になる。`scenes` はこの決まりごとが効く場面を列挙し、値は `skills/scribe/scripts/find_wiki_rule.py` の `SCENES` から選ぶ。該当する場面が無ければ空配列にする。参照コードには Phase 4 で検証した現行コードの位置を `path` + シンボル名 (関数/型/見出し) で書き、行番号は書かない。コード断片の転記はパターンの形自体が本体の場合のみ数行まで。由来は任意の節で、Phase 5 の判定を通った DR だけを書き、該当が無ければ節ごと省く。根拠には元の議論の PR/issue 番号を書き、`.claude/workspace/research/` 由来のものは番号の代わりに `(research)` と書く。research のファイルパスは書かない。

```markdown
---
globs: ["<この決まりごとが効くファイルのパターン>"]
scenes: ["<この決まりごとが効く場面。SCENES にある値のみ>"]
---

# <共通項名>

## 内容

何をする / しないかの言語化 (1 〜 3 文)。

## 定型手順

繰り返す手順 / チェックリスト (あれば)。

## 参照コード

- `path/to/file` の `シンボル名` (何が読めるか 1 行)

## 由来

- `docs/decisions/<NNNN>-<タイトル>.md` (この決定から派生。1 行で何を決めた DR か)

## 根拠

- #12 何があったか 1 行
- #34 何があったか 1 行
- (research) 何が分かったか 1 行
```

## kind: structure ページ

共通項ページとは別に、`kind: structure` を frontmatter に持つ構造ページがある。共通項ページが PR/issue から抽出した繰り返しパターンを書くのに対し、構造ページは 1 つの glob 契約グループ (同じ境界と契約を共有するファイル群) の構造を書く。どちらの骨格を使うかは書き込みの種類で決まり、`pages` の項目が持つフィールドでは決まらない。Phase 3 の抽出対象は PR/issue の共通項パターンに限られるので、`pages` に構造ページが乗ることはない。構造ページがこの骨格に届く経路は `pages` の外に 2 つある。手で書いて足す経路と、Phase 4 手順 4 が行のずれを見つけたときに Phase 6 手順 2 が書き直す経路。節は内容 → 境界 → 契約 → 要求 → 参照コード → 由来で、定型手順・根拠は持たない。由来は見出し自体を必ず持ち、条件を満たす記録が無いときだけ中身を空にする。

```markdown
---
globs: ["<このグループが効くファイルのパターン>"]
scenes: []
kind: structure
---

# <グループ名>

## 内容

このグループが何をするか (1 〜 3 文)。

## 境界

- 何と何が独立し、何が入れ子か (1 行ずつ)

## 契約

| 対象     | 契約     |
| -------- | -------- |
| `<対象>` | `<契約>` |

## 要求

| 対象     | 上限     | 超えたときの挙動 |
| -------- | -------- | ---------------- |
| `<対象>` | `<上限>` | `<挙動>`         |

## 参照コード

- `path/to/file` の `シンボル名` (何が読めるか 1 行)

## 由来

- `docs/decisions/<NNNN>-<タイトル>.md` (この決定から派生。1 行で何を決めた DR か)
```
