# 多層検証

失敗が通過しうる各層にチェックを追加し、別のコードパスやリファクタで同じバグが再発しないようにする。

## 適用タイミング

`use-context-root-cause-analysis` が返す Pattern フィールドで決まる。各値の判定はその skill が定める (§ Pattern の判定)。

| Pattern    | 動作                                                        |
| ---------- | ----------------------------------------------------------- |
| Isolated   | スキップする                                                |
| Recurring  | layer 1〜2 (entry point と business logic) を最低限適用する |
| Systematic | 全層を適用する                                              |

## 層

Pattern で選んだ層のうち、適用条件を満たすものだけを足す。

| Layer | 種別                  | 目的                 | 適用条件                         | 例                                    |
| ----- | --------------------- | -------------------- | -------------------------------- | ------------------------------------- |
| 1     | Entry point           | 不正入力を拒否       | 外部入力が関わる場合             | 必須 param が空ならエラーをスロー     |
| 2     | Business logic        | 不変条件を守る       | ドメイン不変条件が破られうる場合 | mutation 後にエンティティ状態を検証   |
| 3     | Environment guards    | 環境の取り違えを防ぐ | 操作に環境依存リスクがある場合   | テスト環境で破壊的操作を拒否          |
| 4     | Debug instrumentation | フォレンジック記録   | 失敗が再現困難な場合             | リスク操作前に stack trace 付きでログ |

## パターンの適用

1. 不正値の発生元と消費先までデータフローを追跡する
2. 値が通過する全チェックポイントをマップする
3. Pattern により層を選択する。対応は § 適用タイミング
4. マップしたチェックポイントのうち、選んだ層に当たる箇所へ検証を追加する
5. 1 つを bypass して別の層が捕捉することを確かめながら、各層を独立にテストする

## 検証

- [ ] Pattern が層選択を駆動した
- [ ] 各層が独立にテスト可能
- [ ] 少なくとも 1 つの層に bypass テストを実施 (Systematic パス)
