# 文章レビュー

文脈を共有しリンク先を開けるチームメイトに向けて書く。Issue が運ぶのは差分、背景はリンクが運ぶ。消しても読み手が判断を誤らない行は書かない。ここで見るのは Issue 本文に固有の構造で、語彙と文の形は見ない。

## 構造

| チェック       | 質問                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| 問題の提示     | 問題や要望が冒頭の 1〜3 行で述べられているか                                                                    |
| 具体性         | bug は再現手順、feature はユースケースが具体的で、期待結果が推測任せでないか                                    |
| 差分集中       | コードを読めば分かる what を避け、why と完了条件に絞っているか。収まらない分は削るか、別 issue やリンクへ逃がす |
| セクション適合 | 各セクションが見出しの求める内容だけを載せているか                                                              |

## 冗長パターン

下表に無い冗長さも、同じ性質のものは直す。

| パターン       | 修正                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------- |
| doc の書き写し | リンク済み doc やログの再説明はリンク + 要点 1 行に畳む。差分だけ書く                     |
| 決定の重複     | 同じ設計理由は決定が着地する箇所で 1 回だけ述べる。案の比較は本文に入れず、think に委ねる |
| 過剰指定の AC  | criterion は残し、story 名や設定値の列挙といった書き方の詳細を削る                        |
