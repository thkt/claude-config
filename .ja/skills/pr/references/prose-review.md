# 文章レビュー

文脈を共有しリンク先を開けるチームメイトに向けて書く。PR 本文に書くのは差分の意図とレビュー導線。コードが何を変えたかは diff を読めば分かる。読み手の判断を変える行だけを書く。このレビューが確認するのは PR 本文の構成だけ。

## 構造

| チェック       | 質問                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| Why stated     | what でなく変更理由の why が冒頭 1〜3 行にあるか                                     |
| Test evidence  | 実行コマンド、テストファイル、スクリーンショットなど検証が具体的か                   |
| Scope          | 変更が集中しているか、無関係な編集が混ざっていないか                                 |
| Reviewer focus | `focus on X` や `skim Y` でレビュー優先度が明確か。置き場所は pr-writing.md が決める |
| Risk surfaced  | マイグレーション、ロールバック、パフォーマンスのリスクが明示されているか             |

## 冗長パターン

下表に無い冗長さも、同じ性質のものは直す。

| パターン        | 修正                                                                             |
| --------------- | -------------------------------------------------------------------------------- |
| diff の書き写し | 変更したファイルや関数の列挙は diff を見れば足りるので落とす。残すのは変更の意図 |
