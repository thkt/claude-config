# REFERENCE_INDEX.md フォーマット仕様

規約パス `docs/REFERENCE_INDEX.md` が持つべき行形式の正本。`workflows/code.js` の `parseReferenceIndexRows`/`SUPPORTED_GLOB_CHARS`/`BARE_DOUBLE_STAR` が読み取る実装挙動を正として定義する (ADR-0091)。

## 行形式

1 行は `glob`/`description`/`path` の 3 列を持つ Markdown テーブル行として書く。

```
| glob | description | path |
| --- | --- | --- |
| src/*.tsx | コンポーネント規約 | docs/conventions/component-tsx.md |
| - | エラーハンドリングの書式規約。読むかは判断による | docs/conventions/error-handling.md |
```

| 列          | 意味                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------- |
| glob        | この行を実装 step に注入する条件。unit の対象ファイルパスと照合する。`-` は無条件候補 (後述) |
| description | 1 行説明。実装 agent が読むかどうかを判断する材料になる                                      |
| path        | 読ませたいリファレンス文書のリポジトリ相対パス                                               |

## 表の制約

`docs/REFERENCE_INDEX.md` が持つ表は 1 枚だけであり、先頭 2 行 (ヘッダー行 `| glob | description | path |` と区切り行 `| --- | --- | --- |`) の直後に行データが続く形を守る。

パーサ (`parseReferenceIndexRows`) は `|` から始まる行を集め、先頭 2 行を無条件に読み飛ばして残りをデータ行として解釈する。ヘッダー行の文言そのものは検証しない。したがって 2 枚目の表を同一ファイルに追記すると、その区切り行 (`| --- | --- | --- |`) は 3 列の妥当な行として解釈され、`glob: "---"` という一致しない幽霊行が静かに紛れ込む。

3 列に分割できない行 (列数が 3 以外になる壊れた行) は解析結果から除外され、`reference-index: parsed N/M table rows` のログで除外件数が記録される。

## 対応 glob サブセット

`glob` 列に書けるのは次の文字集合だけである (`SUPPORTED_GLOB_CHARS`)。

- 英数字・アンダースコア (`\w`)
- `.` `-` `/` `*`

この文字集合のうち、メタ文字として意味を持つのは次の 2 トークンに限る (`globToRegExp`)。

| トークン | 一致範囲                                                                                                                          |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `**/`    | ディレクトリ 0 階層以上に一致する (`docs/**/*.md` は `docs/readme.md` にも `docs/sub/readme.md` にも一致する)                     |
| `*`      | `/` を跨がない 1 セグメント内の任意文字列に一致する (`src/*.tsx` は `src/button.tsx` に一致し、`src/app/page.tsx` には一致しない) |

`/` が続かない裸の `**` (例: `src/**`) は文字集合チェックには通るが、トークン化では `**/` として認識されず `*` 2 つに分解されて 1 セグメント照合に化ける。静かな取りこぼしを防ぐため `BARE_DOUBLE_STAR` で個別に検出し、対応外として扱う。

`glob` 列とファイルパスの両辺は、先頭の `./` または `/` を正規化 (除去) してから比較する。どちら側が prefix を持っていても一致判定に影響しない。

## `-` 行の意味

`glob` 列が `-` の行は glob 照合の対象外で、unit の対象ファイルに関わらず常に注入候補として提示される。実装 prompt には `Consider reading: <path> (<description>)` の形で載り、読むかどうかは実装 agent の判断に委ねられる。`-` 行は文字集合チェックや `BARE_DOUBLE_STAR` チェックの対象にもならない。

## 未対応行の扱い

対応外と判定された行は照合対象から除外され、実装 prompt に注入されない。除外は黙って起きず、`kind: "unsupported-glob"` の anomaly として `glob` 列の値と理由付きで記録される。

## 注入時の並び順

`glob` が一致した具体的な行 (`Read before implementing: <path>`) は、`-` 行の判断候補 (`Consider reading: <path> (<description>)`) より後ろに置かれる。後の行が勝つ規則と組み合わせることで、具体的な読了命令が判断候補より優先される。

## 見張り基準

インデックスが 1 画面を超えたら注入過多の兆候として見張る (ADR-0091)。行数の閾値と機械検出は stock skill の check-index.js が担う。
