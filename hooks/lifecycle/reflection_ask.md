# reflection-ask

`reflection-ask.py` が Stop hook の additionalContext として送る指示。送るのは `## ask` と `## backlog` の 2 節で、見出しより前のこの説明は送らない。節の中の行頭へ `##` を置くと、`_prompt` がそこから先を読まなくなる。

送信時に置き換えるのは `{transcript}` `{corrections}` `{rule_file}` `{count}` の 4 つ。渡す値は節ごとに分かれている。`## ask` は transcript と corrections を受け取り、`## backlog` は corrections と rule_file と count を受け取る。節をまたいで移すと hook が KeyError で止まり、その失敗は会話にも `git diff` にも出ない。

## ask

reflection-ask: このセッションで踏んだ事象のうち、次のセッションが必ず踏むものを 1 つ書き残す。同じ経路を通るかどうかで判定する。迷ったら書かない。1 件も書かない回があってよい。

### 書かないもの

書かないものは次の 3 つ。

1. 一度きりの調査結果や、ツールの使い方を調べただけの記録
2. 採用を見送った外部ツールの検討記録
3. 規則ファイルへ書けば済むもの

### 誰が書くか

追記は Agent tool の subagent 1 体に任せる。あなた自身は追記しない。渡すのは次の 2 つに限り、書き込み先を増やさない。

| 渡すもの   | 値            |
| ---------- | ------------- |
| transcript | {transcript}  |
| 追記先     | {corrections} |

### subagent の作業

追記と掃除を同じ回に行う。追記先へ至るディレクトリが無ければ作り、残すものが無ければ何も書かない。

追記は、内容に合う見出しの表の末尾へ 1 行足す。見出しは「外部ツールの実測挙動」と「ハーネスの教訓」の 2 つ。見出しの新設も、既存行の並べ替えもしない。1 行は 200 字以内に収め、超えるなら要点だけ残す。

掃除は次の 2 つ。

1. 一度きりの事象報告に留まる行を消す。消す前に現物を読み、書かれた状態と食い違うことを確かめる
2. 対象列が同じ行を 1 行へまとめる。後の行が前の行を否定している場合も 1 行へまとめる

消さないものは次の 3 つ。他所の規則ファイルへ移せる規則を持つ行、その事象に気付く経路を持つ行、現物を読んで確かめられなかった行。

### 返し方

subagent の完了を待たずにターンを終える。subagent が返すのは「追記 N 件、削除 M 件、統合 K 件」の 1 行に限る。完了通知が届いたら、あなたはその 1 行をそのまま伝え、内容を説明し直さない。

## backlog

追記先には、対象列が {rule_file} を指す行が {count} 行溜まっている。同じ subagent に、その行の {rule_file} への統合まで行わせる。この回に限り、subagent は追記先に加えて {rule_file} へも書く。{rule_file} が `.ja/` 側を持つならそちらも含み、追記先と {rule_file} の他へは書かない。

統合の作法は次の 3 つ。

1. 移動でなく蒸留で、規則そのものと、その事象に気付く経路だけを {rule_file} へ書く
2. 実測値と再現手順は落とすか、{rule_file} の references/へ回す
3. `.ja/` 側を持つなら `.ja/` を先に書き、同じ内容を英語側へ反映する

{rule_file} へ書き終えたら、その内容の行を追記先から消す。この回の subagent が返す 1 行は「追記 N 件、削除 M 件、統合 K 件、{rule_file} へ L 件」にする。
