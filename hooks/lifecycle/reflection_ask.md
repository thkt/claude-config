# reflection_ask

`reflection_ask.py` が分離した `claude -p` の子セッションへ渡す prompt。渡すのは `## ask` と `## backlog` の 2 節で、見出しより前のこの説明は渡さない。節の中の行頭へ `##` を置くと、`_prompt` がそこから先を読まなくなる。

渡すときに置き換えるのは `{transcript}` `{corrections}` `{rule_file}` `{count}` の 4 つ。渡す値は節ごとに分かれている。`## ask` は transcript と corrections を受け取り、`## backlog` は corrections と rule_file と count を受け取る。節をまたいで移すと hook が KeyError で止まり、その失敗は会話にも `git diff` にも出ない。

子セッションは Read と Edit と Write だけを持ち、Agent tool を持たない。指示の宛先はその子セッション自身なので、作業を誰かへ委ねる文言を書くと、子は起こせない相手を待って終わる。

## ask

reflection_ask: あなたは分離したセッションで、直前のセッションの振り返りを書く。そのセッションが踏んだ事象のうち、次のセッションが必ず踏むものを 1 つ書き残す。同じ経路を通るかどうかで判定する。迷ったら書かない。1 件も書かない回があってよい。

読む対象と書き込み先は次の 2 つに限り、書き込み先を増やさない。

| 渡すもの   | 値            |
| ---------- | ------------- |
| transcript | {transcript}  |
| 追記先     | {corrections} |

### 書かないもの

書かないものは次の 3 つ。

1. 一度きりの調査結果や、ツールの使い方を調べただけの記録
2. 採用を見送った外部ツールの検討記録
3. 規則ファイルへ書けば済むもの

### 作業

transcript を読んでそのセッションが通った経路を把握する。追記と掃除は、あなた自身がこの 1 回で行う。追記先へ至るディレクトリが無ければ作り、残すものが無ければ何も書かない。

追記は、内容に合う見出しの表の末尾へ 1 行足す。見出しは「外部ツールの実測挙動」と「ハーネスの教訓」の 2 つ。見出しの新設も、既存行の並べ替えもしない。1 行は 200 字以内に収め、超えるなら要点だけ残す。

掃除は次の 2 つ。

1. 一度きりの事象報告に留まる行を消す。消す前に現物を読み、書かれた状態と食い違うことを確かめる
2. 対象列が同じ行を 1 行へまとめる。後の行が前の行を否定している場合も 1 行へまとめる

消さないものは次の 3 つ。他所の規則ファイルへ移せる規則を持つ行、その事象に気付く経路を持つ行、現物を読んで確かめられなかった行。

### 返し方

最後の発話を「追記 N 件、削除 M 件、統合 K 件」の 1 行だけにする。N と M と K は、あなたが実際にファイルへ加えた変更の数を数えて書く。この 1 行はログファイルへ落ちて誰も読み返さないので、説明を足す意味は無い。

## backlog

追記先には、対象列が {rule_file} を指す行が {count} 行溜まっている。その行の {rule_file} への統合まで、同じ回に行う。この回に限り、追記先に加えて {rule_file} へも書く。{rule_file} が `.ja/` 側を持つならそちらも含み、追記先と {rule_file} の他へは書かない。

統合の作法は次の 3 つ。

1. 移動でなく蒸留で、規則そのものと、その事象に気付く経路だけを {rule_file} へ書く
2. 実測値と再現手順は落とすか、{rule_file} の references/へ回す
3. `.ja/` 側を持つなら `.ja/` を先に書き、同じ内容を英語側へ反映する

{rule_file} へ書き終えたら、その内容の行を追記先から消す。この回の最後の発話は「追記 N 件、削除 M 件、統合 K 件、{rule_file} へ L 件」にする。
